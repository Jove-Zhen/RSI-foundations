0–2 min · Working definition

What makes an improvement recursive?

In recursive self-improvement (RSI), a later improvement round starts from an accepted change and actually uses it when proposing, checking, or selecting another change.

What happens in one round

A task run uses the current system to produce an answer or action. An improvement round changes the system that runs the task. It starts with a version and its records, proposes an edit, and tests the candidate against a baseline. An acceptance rule decides which version and records to retain.

One checker, four kinds of evidence

Suppose a solver submits a calculation that uses one of its input numbers twice. We can trace what happens when the system catches the error and decides what to keep.

Local revision
Feedback catches the repeated number. The solver corrects this answer.
Persistent reuse
A check that catches repeated inputs passes evaluation, is saved, and is used on a new task.
Recursive inheritance
A later improvement round uses the accepted check’s rejection logs to revise the solver’s prompt. This is evidence for minimal RSI even if the new prompt is ultimately rejected.
Recursive progress
A controlled comparison shows that giving the later round access to the retained check and logs helps it produce a better successor.

2–5 min · Case comparison

What does each paper hand off?

We group the cases by what they change: an answer, an agent, a training-data generator, or an experiment plan. In each case, the handoff is what the next stage actually receives.

Behavior

Self-Refine

Setup
A fixed language model drafts an answer, critiques it, and revises it. An external test or rating evaluates the result.
Handoff
The draft and its critique guide the next revision of the same task.
What the evidence supports
Better final answers support within-task improvement. To isolate the effect of the critique, compare with fresh samples under the same call budget.

Agent systems

Darwin Gödel Machine

Setup
An agent edits its own code. The resulting agent is evaluated on coding tasks, with the base language model fixed.
Handoff
A selected agent from the archive becomes a parent and writes the next modification. The lineage records which version took over.
What the evidence supports
The lineage shows actual use of selected versions. To test whether an evolved agent is a better improver, give it and the initial agent the same target code, logs, edit request, and budget. Then compare the agents they produce.

Models and data

STaR

Setup
The Self-Taught Reasoner writes a rationale and an answer. The known answer lets the pipeline filter examples. For initially incorrect answers, it can supply the answer as a hint while constructing training data.
Handoff
The selected examples train a model that takes over rationale generation in the next round. Evaluation supplies the question without its correct answer.
What the evidence supports
The trained model demonstrably takes over data generation. To compare two generators, match sample count, task difficulty, and training steps, then evaluate models trained from the same initial weights.

Research processes

The AI Scientist

Setup
The agent starts from runnable research code, edits it to run an experiment, and records the result. An error can trigger a repair; a valid result can motivate a change to the experimental plan.
Handoff
An experiment’s results and the resulting plan can carry into the next experiment within the same project.
What the evidence supports
A completed run establishes that the code ran. To establish a change in research practice, trace a specific result to a changed hypothesis or control and verify that the next run implements it.

5–8 min · A comparison we would run

Does inheritance improve the next round?

Suppose a solver has accepted an improved checker and saved its rejection logs. We want to test whether giving a later improvement round that checker and those logs helps it produce a better solver.

Match the starting point and vary inheritance

In each pair, give both rounds the same solver to edit, the same edit request, the same environment, and the same call budget. Each round outputs a new solver, which we call a successor.

With inheritance
The improvement round receives the accepted checker and its structured rejection logs.
Previous state
The improvement round receives the previous checker and its original logs.

Score what each round produces

Use one independent scoring rule and the same held-out tasks for both successors. Keep those tasks separate from the tasks used to propose or select changes.

Average paired difference

Δ = mean [Q(Ykeep) − Q(Yprevious)]

Ykeep and Yprevious are the successors from the two conditions. Q scores a successor on the held-out tasks. In two illustrative pairs, scores of 70 versus 65 and 81 versus 80 give gaps of 5 and 1. Their mean, Δ, is 3 points.

Interpret the result

Read the logs to see where inheritance affected a proposal or test. Repeat the comparison with multiple paired seeds and report how much the score gap varies. A reliable positive gap supports a benefit from the checker and logs together under these conditions. To estimate the logs’ contribution, keep the checker fixed and vary only whether the logs are available.
